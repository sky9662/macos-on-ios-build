Phase 1: cross-compile the libraries, verify ARM64/iOS platform, exported
OSMesa/Vulkan APIs and link an independent compile-only consumer. This is not
runtime validation. Phase 2: implement NSOpenGLContext / desktop symbol
resolution and Metal presentation using OSMesa; then validate a real shader
draw/read on device. Preserve the existing GLES backend as a fallback.
No change to game JIT, security, or packaging gates.

## Round 44 failure / round 45 correction
Run 45797917173: MoltenVK succeeded; Mesa ninja stopped at 474/928 compiling generated program_lex.yy.c. The compiler invocation included -std=c11, -DHAVE_ENDIAN_H, iPhoneOS27.1.sdk and arm64. Mesa 25.0.7 src/util/u_endian.h line 93 rejected unset UTIL_ARCH_LITTLE_ENDIAN / UTIL_ARCH_BIG_ENDIAN. The header prioritizes HAVE_ENDIAN_H over the Apple branch and only tests legacy aliases there. Fix: prefer Clang target byte-order macros on Apple targets, retaining the existing generic/Apple fallbacks and final consistency check. No hardcoded architecture override or weakened warning flags. Download and SHA256-check the pinned tarball early; dry-run/apply the patch to the exact header and compile the strict C11/C++17 regression with HAVE_ENDIAN_H before building MoltenVK. Then copy the patch into the disposable BCD recipe's existing numbered patch series, retaining it with the build's source recipes. No change to upstream repositories or existing GLES/JIT workflow. Actual successful full Mesa build remains unverified.
Reference header: https://github.com/chaotic-cx/mesa-mirror/blob/mesa-25.0.7/src/util/u_endian.h

## Round 48 success / round 49 IOSurface presentation ring
Run 45807741724 succeeded both jobs (artifact 15110731827). User requested reuse of available BCD implementations. The pinned BCD WiniosGL.m (https://github.com/thebcd69/bcd-games/blob/8c784fe01359ece82158567676948628f5f41099/app/Madeira/Winios/WiniosGL.m) uses an IOSurface ring, OSMesa row pitch, glFinish before handoff, and per-slot Metal completion rather than waiting on every swap. Its implementation is coupled to Wine HWND, EAGL, BCD frame accounting and GPL-covered app code. We reuse the existing BCD-built MIT Mesa patch set and libraries directly; this Mac adapter implements the IOSurface architecture with public APIs, no GPL application code copied into the diagnostic. Preserve source notices; review compatible licensing before direct GPL source integration. Three IOSurface-backed Metal textures replace the heap staging buffer and CPU replaceRegion upload. Limit total backing allocation to 192 MiB per ring, validate row pitch/size, acquire new slot before handing the old one to Metal, wait on its own reader before reuse, maintain main-thread context ownership and preserve previous storage until successful rebind. No claim of zero-copy GPU rendering: OSMesa still performs a readback into the surface. Device regression draws seven alternating colors, verifies actual written center bytes, counts submitted frames and waits for final Metal completion. The adapter skips inactive-app presents without blocking UIKit; it does not protect unrelated GL work in the background. Runtime, orientation, resource limits and speed remain unverified; no JIT changes.
