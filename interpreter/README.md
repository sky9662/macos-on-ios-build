# Bounded ARM64 interpreter feasibility

This is an independently written experimental subset, not a replacement for the game's JIT or a complete AArch64 engine. It interprets immutable 32-bit A64 instruction words as data, with 31 zero-extended guest registers, a separate bounded little-endian guest data buffer, and a finite instruction budget. It accepts LSL-shifted 32-bit AND/ORR/EOR, immediate ADD/SUB without flags, unsigned-offset 32-bit LDR/STR, CBZ/CBNZ, B, and a synthetic RET boundary. All other opcodes, stack-pointer usage, indirect host calls and out-of-range guest accesses are rejected. No executable allocation or host memory alias is used. On error, discard the partial guest state.

Tests compare an independently authored full-adder fixture (all eight inputs) and memory-update loop (64 cases) against native ARM64 assembly on macOS; Linux runs the same expected outputs with sanitizers. iOS compile checks are not device runtime tests. No game content, disassembly, offsets or private records are committed. No third-party code is included. Reference design context: UTM SE and iSH ARM64, as discussed in jit/SOURCE-INTEGRATION.md.

The local audit suggests a candidate generated-code boundary; it does not establish ABI, all indirect paths, emitted opcode coverage, callbacks, flags, stack, memory ownership, performance or a lawful integration interface. This subset deliberately has none of those integrations. A broader engine should be evaluated against the real requirements before expanding this prototype. The existing packaging/JIT gate remains unchanged.
